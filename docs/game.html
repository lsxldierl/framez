Game

The Game data workspace's menu: what the game reads from the clip, how Roblox plays it, and the scripts that carry it into the game.

Add event here...Game > Add event here..., or the events lane

Names a moment of the clip at the playhead: Hit, Footstep, Sound, SpawnVFX or any word, with an optional value (Slash1, Left). The save writes it as a Roblox KeyframeMarker, which a game script hears when the clip reaches that frame.

  1. Move the playhead to the frame.
  2. Choose Game > Add event here...
  3. Type a name and press Enter, or click one of the names under the field. Add a value if the script needs one.

the hit frame of an attack, footsteps, a sound or effect that must land on one frame.

Also on the timeline's right-click, the + on the Events row, and Ctrl+K. Several events can share a frame.

Edit event here... / Delete event hereGame > Events, or the events lane

Changes the name and value of the event at the playhead, or deletes it. With two or more on the frame, Edit lists them. Each change is one undo step.

Both rows are greyed when the playhead is not on an event.

Go to eventGame > Events > Go to event, or the events lane

Moves the playhead to the next or the previous frame with an event. Next event and Previous event are greyed when there is none in that direction.

Hearing an event in the gamea game script

Each event fires AnimationTrack:GetMarkerReachedSignal(name) with the event's value:

local track = animator:LoadAnimation(attackAnimation)

track:GetMarkerReachedSignal("Hit"):Connect(function(value)
	-- the event's value: "Slash1", or ""
	dealDamage(value)
end)

track:GetMarkerReachedSignal("Footstep"):Connect(function(foot)
	playStepSound(foot)   -- "Left" or "Right"
end)

track:Play()

Names are case-sensitive: "Hit" is not "hit". Events go with the saved clip. Publish again after adding them. An event after the last key makes the clip that long in the game.

Impact frame hereGame > Impact and flash > Impact frame here, or the timeline's right-click

Adds an Impact event at the playhead and opens its page in the Inspector, where you build a screen look for the hit: a white or black frame, a tint, solid figures, impact lines, a camera shake and a freeze. Double-click an Impact pin, or Rename, to open the page again. Every change is one undo step and shows in the view at once. Scrub across the event to see each frame.

  • Look: Start from picks a starting point: White, Black, Mono, Tint, Strobe, Flash, Dark flash, or your own saved looks under My looks (each with Use and Delete). Name, and Save as my look (kept for every place).
  • Steps: an impact can be several looks one after another. Pick a step and set its frames. Add step copies the picked one; Remove step deletes it.
  • World (for the picked step): Brightness (3 washes the world white, -3 black), Contrast, Saturation (-1 is black and white), Tint (type FF3B30 or 255 59 48).
  • Figures (for the picked step): Solid figures draws the characters as solid shapes over the world. Fill colour and See-through, Outline colour and See-through, and Seen through walls.
  • Lines (for the picked step): Impact lines on or off, Colour, Count, Thickness (px), Clear middle (%), Length (%), See-through (%), New lines every frame and From (Character or Screen).
  • Who: Figures is This character, or Near it with a Reach in studs. Seen by is Its player or Everyone.
  • Timing: Fade in and Fade out (frames), Fade curve (how the fades speed up and slow down, with every curve and where it slows) and Strength (scales the whole look).
  • Camera (for the whole look): Shake (studs), Shake speed (per second) and Zoom (degrees; below 0 zooms in). Shake and zoom show while playing or looking through a scene camera.
  • Hit-stop (for the whole look): Freeze (frames). The characters' animations hold still for that many frames. It plays in the game and in Play as Roblox will.

a heavy hit that whites out the screen for one frame, a finisher with black figures on a red world.

Also in Find a command (Ctrl+K). To play it in the game, see Impact frames and flashes in the game.

Flash hereGame > Impact and flash > Flash here, or the timeline's right-click

Adds a Flash event at the playhead and opens the same page as an impact frame, starting from the Flash look: full on its frame and fading out. Change it the same way: fade in, a dark flash (negative Brightness), a tint, any curve.

Also in Find a command (Ctrl+K).

Impact frames and flashes in the gameGame > In the game

Game > In the game > Effects in the game adds the FramezEffects script, which plays impact frames and flashes whenever the clip plays. FramezEffects plays every look as built. A look set to Seen by Everyone shows for everyone who sees the character play it; Its player shows only for that player's own character. The screen option in the LocalScript changes who counts as its player:

require(game:GetService("ReplicatedStorage"):WaitForChild("FramezEffects")).start({ screen = "all" })

Your own scripts can also listen with track:GetMarkerReachedSignal("Impact") and track:GetMarkerReachedSignal("Flash").

Hit windowsGame > Hit windows, or right-click the Hit windows row

Marks a range of frames the game reads, with data of its own: an attack that can hurt, a parry, invulnerable frames, the frames a combo can cancel. Windows show as bars on the Hit windows row under the rig, coloured by kind.

  1. Move the playhead to the first frame of the attack.
  2. Choose Game > Hit windows > Add hit window here.
  3. Drag the bar's middle to move it and an end to trim it.
  4. Pick the bar and fill in its page in the Inspector.
  • Add hit window here: starts a Hit window at the playhead, on the held weapon (or the hand), with Damage 10.
  • Add window here: Hit window, Parry window, Block window, Invulnerable window, Cancel window, Combo window, or a kind you type.
  • Edit hitbox in the view: makes the hitbox a part you change with Studio's tools. It is greyed until a window with a hitbox is picked.
  • Show hitboxes: draws every hitbox in the view.
  • Right-click a bar: Go to its start, Kind, Edit hitbox in the view, Duplicate and Delete (Del). Overlapping windows show in bands. Esc lets go.
  • The page: Name, Kind, Starts at and Ends at. Hitbox holds the part or held object it moves with (or No hitbox), Box or Ball, Size, Place on the part and Turn (drag the numbers), Edit in the view and Fit to the part. Data holds any fields and values (Damage 25, Knockback 30, Element Fire) and Add field, with chips for Damage, Knockback, Stun and Element. The page also has Duplicate and Delete.

While the playhead is inside a window, its hitbox shows on the rig as a see-through box or ball with edges; the picked window's is dimmer outside it. Edit in the view makes the hitbox a real part in Studio's selection. Studio's Move, Scale and Rotate tools change it, and the window reads the change back as one undo step. Click away to finish.

attacks the game checks frame by frame, parries, i-frames and the frames a combo can cancel.

The save writes HitStart at its first frame, its value the window as JSON (name, data, hitbox), and HitEnd at its last; another kind writes its own name (ParryStart, ParryEnd). Every timing tool and Mirror move and reflect them. To use them in the game, see Hit windows and foot contacts.

Foot contactsGame > Foot contacts, or right-click the Foot contacts row

Marks where each foot is down on the floor. They show on the Foot contacts row, a strip for each foot (L, R) with a bar while the foot is down.

  • Find foot contacts: reads them off the clip as it plays. A foot is down while its sole is within Height (0.25 studs) of its lowest point for Shortest (2 frames) or more. Its values open in Adjust.
  • LeftFoot down here and RightFoot down here: add a contact by hand at the playhead.
  • Clear foot contacts: removes them all. It is greyed when there are none.
  • Edit a bar: drag it to move it, drag an end to trim it, right-click to delete it.

footstep sounds and dust, and walks and runs the game blends at the same step.

The save writes FootDown at each landing and FootUp at each lift, valued Left or Right.

Body maskGame > Body mask, or Inspector > Clip > In the game

Sets the parts this clip plays on in the game. Save writes keys only for the parts in the mask; in the game, the parts outside it play whatever plays under it. An attack masked to Upper body plays over the run. The clip keeps every key in Framez.

  • Masks: Whole body, Upper body, Lower body, Arms, Legs and Head. More masks holds Left arm, Right arm, Left leg, Right leg and Arms and held objects. On R6, Upper body is the head and arms; the torso stays with Lower body.
  • Edit mask...: opens the mask editor (Edit mask...) to name a mask, tick each part with its share, and keep it in My masks.
  • Add a masked copy: Upper body, Lower body, Arms, Legs or Head. Saves another clip from the same keys beside this one, with its own name ending (_UPPER, _LEGS) and mask. It is saved after the _MOVING copy each time you save. The Inspector lists the copies with their masks and Remove.

attacks and casts over locomotion, a wave over any idle.

In the game a part plays fully or not at all: any share above 0 counts as in. Shares between 0 and 100 % play in Framez's layers and clip blocks, which have masks of their own: Key > Layers and a block's right-click.

Play as Roblox willGame > Play as Roblox will

Plays the clip on a see-through copy beside the rig through Roblox's own Animator. Each event's name flashes over its head, and in the status line, as Roblox fires it. Hit windows flash as their markers are reached. When Framez is not playing, the copy shows the playhead's frame.

the last check before publishing.

The Test bench's Compare tab shows where Roblox's playback differs from Framez's.

Test bench...Game > Test bench...

A floating window that tests how the clip plays in Roblox: in a running game, joined to the clips around it, on other body shapes, under a game camera, and against other versions of itself. It has no play buttons of its own: Space, the playhead and the timeline drive it.

At the top, a test scene picker with a more button: Save as my test scene, Save in this place and Delete. Under it, five tabs. A tab shows a green dot while its part is in the test. A dot under each event's pin shows whether it fires: green on time, red late or missing from the save.

  • Game: Slot (Action on a key, Idle, Walk, Run, Jump, Fall, Climb, Swim), Key, Priority, Fade in / out, Weight and Speed.
  • Transitions: the clips before and after this one on two lanes, counted in frames.
  • Bodies: R15 Classic, Rthro, Slender, Scaled 1.5, My avatar and any model from the place. R6 rigs get R6, Scaled 1.5 and Scaled 0.75.
  • Camera: Free, Third person, First and Shoulder.
  • Compare: the clip as Roblox plays it, the last save, or another save.
  1. Open Game > Test bench... and pick the Game tab.
  2. Set Slot, Key, Priority, Fade in / out, Weight and Speed.
  3. Press Try in the game.

Try in the game: while Studio is in Play, the clip runs on the player's character. An action plays on its key; a slot swaps the Animate script's animation for the clip and puts the old one back after. An edit made in Framez reaches the playing character a moment later. A status line shows the game's state. If another animation would play over the clip, the line reads "X plays over it at P: raise Priority." Closing the bench turns the game test off.

Transitions: a block's body sets how long it plays; its left edge sets the fade into it. Right-click a block to take it off. Drag on the ruler to scrub the join. Below, the picked block's Clip, Plays for, Fade, Weight, Speed and Priority. The loop seam shows the worst limb in degrees.

Bodies: each body is placed beside the rig (in a row, behind, or on it) with its feet on the floor, and plays the clip through its own Animator. Marks flag runs of frames where a hand or foot goes through a torso, or a foot is more than 0.15 studs under the floor. Click a mark to go to its first frame.

Camera: sets the distance, the field of view and the body it follows. It drives Studio's camera only while Framez plays.

Compare: shows the differences as Ghost, Side by side or On the rig, with Tint from (degrees) to colour the limbs that differ. It names the most changed limb (degrees and frame) and adds a Difference row to the tracks.

checking a skill plays at the right priority in a real game, a walk joining a run, a clip on a tall or small body, a clip under a shoulder camera.

Join withGame > Preview with another clip > Join with

Plays the end of another save of this rig into the start of this one. Pick the save from the list. Stop ends the join; it is greyed when none is playing.

checking a skill comes cleanly out of the idle or run.

Blend withGame > Preview with another clip > Blend with

Plays this clip and another save of this rig in a Roblox Blend1D, on the see-through copy, through Roblox's own Animator. Drag Blend value to mix them, and set where each clip sits on the scale. Under the fields, a ruler shows both clips' feet across their own loops, 0 to 100 %. A white bar is a foot on the floor, and a red mark is where it lands. Closing the box stops it.

a walk that turns into a run with speed, or an idle that eases into a guard.

Match stepsGame > Preview with another clip > Blend with > the box's button

Retimes this clip to land its left foot at the same point of its loop as in the other clip, and stretches each half to match the right foot too. Every key moves; none is added except at the loop's start and end. Events, weapon switches and face keys move with their frames (a face key that would land on another refuses the match, as limb keys do). The ruler and the blend update, and one Ctrl+Z puts the timing back.

two cycles that will blend in the game: walk and run, run and strafe, forward and back.

Match steps will not squeeze two keys of one limb onto one frame: delete one, or make the clip longer. It needs a clip whose last frame matches frame 0, and both feet touching the floor.

Add on topGame > Preview with another clip > Add on top

Plays another save of this rig added over this clip, through Roblox's Add node, with a weight you drag. Use it with clips made by Save as additive.

Blend directions...Game > Preview with another clip > Blend directions...

Plays up to five saves in a Roblox Blend2D: an idle at the centre, then forward, back, left and right. Each has an X / Y place (X right +, left -; Y forward +, back -). Click a name to pick from this rig's saves. Play starts the see-through copy. Drag X and Y, or the red handle on the pad, to steer it.

checking a full set of movement cycles together before building the game's locomotion graph.

In the game, put the same clips in a Blend2D at the same places, with X and Y set from the move direction in the character's own space. Between the places, Roblox mixes the nearest clips; it does not need a full grid.

Aim offset poses...File > Export > Aim offset poses... (Animate workspace)

Saves nine poses that aim from the pose at the playhead: left, right, up, down and the corners. The chest turns 60 %, the head the rest, and the arms all of it (or they ride the chest). On R6 the hips turn back and the legs stay where they stand. They are saved as NAME_AIM_C, _L, _R, _U, _D, _UL, _UR, _DL and _DR, additive or as full poses, for a Blend2D with X = yaw and Y = pitch from -1 to 1. The copy beside the rig aims them live: drag Yaw and Pitch.

a character whose upper body follows the camera or a target while the legs play their own animation.

The command is in the Animate workspace's File > Export menu. Find a command (Ctrl+K) lists it from any workspace.

Put the scene in the game...Game > In the game > Put the scene in the game...

Opens the dialog that writes the open scene into the game. It is the same command as Scene > Put in the game... (Put in the game...) and is greyed until a scene is open.

Face swaps in the game...Game > In the game > Face swaps in the game...

Says whether this game has FramezFace, and adds it: ReplicatedStorage.FramezFace and StarterPlayerScripts.FramezFaceClient. Show the script shows both, to copy. To take them out, delete both in the Explorer.

If Studio stops Framez from adding scripts, allow it: Plugins tab > Manage Plugins > Framez > Script injection.

Held objects in the gameGame > In the game > Held objects in the game

Adds ReplicatedStorage.FramezHeld and StarterPlayerScripts.FramezHeldClient. Every clip where an object changes holders then moves it in the game too, for every player, and puts it back when the clip stops. An object held by a bone follows that bone too. Delete held objects from the game takes the scripts out again.

Effects in the gameGame > In the game > Effects in the game

Adds ReplicatedStorage.FramezEffects and StarterPlayerScripts.FramezEffectsClient. They play impact frames, flashes and squash and stretch from any clip saved by Framez, on any character. Delete effects from the game takes the script out of the game; Ctrl+Z brings it back.

FramezEffects plays every look as built. A look set to Seen by Everyone shows for everyone who sees the character play it; Its player shows only for that player's own character (the screen option in the LocalScript changes who counts as its player).

FramezEffects also plays the effects keyed in Framez (Effects on the timeline) and any keyed property (Key any property) from the clip, on any character. An effect the game's character does not have is copied from ReplicatedStorage.FramezVFX, which every save writes.

Run it again on a game that already has it to bring FramezEffects up to date with VFX packs.

Hit windows and foot contactsGame > In the game > Hit windows and foot contacts

Adds ReplicatedStorage.FramezGameData. It turns a clip's hit windows into hits and its foot contacts into footsteps, on the server or a client:

local GameData = require(game.ReplicatedStorage.FramezGameData)
local track = animator:LoadAnimation(attackAnimation)

GameData.hits(track, character, function(hit)
	-- each character the hitbox touches, once per window
	hit.humanoid:TakeDamage(hit.data.Damage)
end)
GameData.footsteps(track, character, stepSound)   -- a Sound, played at the foot
track:Play()

Also: GameData.windows(track, { "Parry" }, onStart, onEnd) and GameData.isOpen(track, "Parry") for any kind of window; GameData.phase(track) and GameData.sync(walkTrack, runTrack) start a run at the walk's step. Its first lines list every call. On a skinned rig it finds a Bone by name or role, and plays footsteps at a foot bone's place. Delete hit windows and foot contacts from the game takes FramezGameData out of the game; Ctrl+Z brings it back.

Delete held objects from the gameGame > In the game > Delete held objects from the game

Takes FramezHeld and FramezHeldClient out of the game. It is greyed when the game has no held object script. To add them again, use Held objects in the game.

Delete effects from the gameGame > In the game > Delete effects from the game

Takes the FramezEffects script out of the game. Ctrl+Z brings it back. To add it again, use Effects in the game.

Delete hit windows and foot contacts from the gameGame > In the game > Delete hit windows and foot contacts from the game

Takes FramezGameData out of the game. Ctrl+Z brings it back. To add it again, use Hit windows and foot contacts.
